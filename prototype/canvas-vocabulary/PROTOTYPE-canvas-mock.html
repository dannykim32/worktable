Design note: why the canvas is a companion, not a chat client

documentv3 · just now

Decision

The terminal agent host stays the conversation driver. The browser page is a companion canvas: the agent publishes artifacts to it, and the human sends selection-anchored ask-backs from it. The framework owns exactly two flows — agent → canvas rendering, and canvas → agent ask-backs. Try selecting any sentence in this paragraph to see the ask-back affordance this design exists for.

Why not a browser chat?

Rebuilding streaming, interrupts, permission prompts, and session lifecycle is a large project orthogonal to the actual value here: the rendering boundary and artifact quality. The core motivation — “ask about a specific paragraph” — needs an anchor, not a chat box.

Honest absence: when the agent cannot render something truthfully (e.g. “summarize 5,471 directories in one artifact”), it declines with a reason. The canvas renders that refusal as a first-class card, never a fabricated visual.
